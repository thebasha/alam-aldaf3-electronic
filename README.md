# عالم الدفع الإلكتروني | Alam Electronic Payment

تطبيق ويب وAndroid تجريبي ثنائي اللغة (العربية والإنجليزية) وبالعملة العراقية (IQD).

## الوظائف الموجودة
- تسجيل حساب وتسجيل دخول واستعادة كلمة المرور عبر Firebase Authentication (Email/Password).
- ملفات المستخدمين وإعدادات الخصوصية واسم المستخدم عبر Cloud Firestore.
- خدمات الدفع والشحن كطلبات ترسل للمراجعة؛ لا تنفذ عمليات مالية تلقائياً.
- إعلانات العملاء مع صور مضغوطة، مراجعة إدارية، وأقسام مثل الإكسسوارات والهواتف والبطاقات والألعاب والاتصالات والإنترنت والعقارات والسيارات والحيوانات الأليفة.
- عرض الإعلانات المعتمدة، تفاصيل المنتج، وسلة مستقلة لكل عميل.
- إرسال طلبات شراء المنتجات إلى الإدارة بحالة انتظار الدفع.
- رسائل الدعم والاقتراحات والشكاوى.
- لوحة إدارة محمية بصلاحية Firebase Custom Claim باسم `admin: true`.
- بناء APK تجريبي عبر GitHub Actions.

## بنية الملفات
- `index.html`: واجهة GitHub Pages.
- `www/index.html`: نسخة الويب التي يضمّنها تطبيق Capacitor على Android.
- `firestore.rules`: قواعد أمان Firestore.
- `storage.rules`: قواعد أمان Storage.
- `firebase.json`: ربط ملفات القواعد مع Firebase.
- `ads.js`: جسر AdMob.

## إعداد Firebase
التطبيق مضبوط حالياً على مشروع Firebase بالمعرّف:
`alam-aldaf3-electronic-922f5`

1. في Firebase Console، تأكد من أن المشروع أعلاه هو المشروع الصحيح الذي تملكه.
2. فعّل Authentication > Sign-in method > Email/Password.
3. أنشئ قاعدة بيانات Cloud Firestore.
4. أنشئ Cloud Storage إذا كنت ستستخدم رفع الملفات إلى Storage؛ صور إعلانات النسخة الحالية تحفظ مضغوطة داخل مستند الإعلان في Firestore.
5. انشر قواعد الأمان من Firebase Console أو عبر Firebase CLI.
6. لنشر القواعد من GitHub Actions، أضف في إعدادات المستودع:
   - Actions Secret باسم `FIREBASE_SERVICE_ACCOUNT` يحتوي JSON لحساب خدمة مخصص للنشر مع صلاحيات Firebase Rules المطلوبة.
   - بعد حفظ السر، شغّل Actions > Deploy Firebase security rules > Run workflow. معرّف المشروع مضبوط في ملف Workflow ليتطابق مع إعداد التطبيق.
7. لا ترفع ملف حساب الخدمة أو مفاتيحه إلى GitHub ولا ترسلها في المحادثات. امنح صلاحية المدير فقط من بيئة موثوقة باستخدام Firebase Admin SDK وCustom Claims.

## حدود مهمة قبل الإطلاق
- طلبات زين كاش وMastercard وSuper Qi هي طلبات مراجعة فقط؛ لا يوجد حالياً تكامل دفع حي أو تحصيل أموال آلي.
- طلب شراء المنتج لا يعني أن الدفع تم؛ يبقى بانتظار التحقق اليدوي من الإدارة.
- بعض الطلبات تحتفظ بنسخة محلية عند فشل الاتصال، ويعرض التطبيق الآن تنبيهاً واضحاً بأنها لم تصل إلى الخادم.
- يجب نشر قواعد Firebase على المشروع الصحيح قبل الاعتماد على مزامنة الإعلانات والطلبات.
- هذه نسخة APK Debug للاختبار وليست إصداراً موقعاً جاهزاً للنشر العام.
- يلزم اختبار شامل على أجهزة فعلية ومراجعة إعدادات Firebase والخصوصية وسياسات المتاجر قبل الإطلاق.

## بناء APK
يعمل GitHub Actions تلقائياً عند الدفع إلى `main`. بعد نجاح بناء Android، حمّل Artifact باسم `alam-aldaf3-electronic-debug-apk` من صفحة تشغيل workflow.

## نشر الواجهة
تُنشر واجهة الويب عبر GitHub Pages عند تحديث المستودع. نشر ملفات GitHub لا ينشر قواعد Firebase تلقائياً؛ يجب نشر القواعد بصورة مستقلة.
